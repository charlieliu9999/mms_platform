# 文件生产和更新规则

## 核心原则

**禁止随意创建新文件。所有工作记录必须追加到指定文件，不得生成独立报告。**

---

## 允许写入的文件清单

### 1. 工作日志（强制使用）
**文件**：`docs/WORK_LOG.md`

**格式**：
```markdown
## YYYY-MM-DD
- 简要描述工作内容（1行）
  - 关键细节（可选，2-3个要点）
- 待完成：未完成项
```

**示例**：
```markdown
## 2026-08-17
- 修复血管成像匹配bug：CE-MRA/MRV节点去重
  - 影响：CT 56项 + MR 38项
  - 验证：A/B测试零退化
- 待完成：DR体位项标准库补充
```

### 2. Bug追踪
**文件**：`docs/reports/audit-issues-tracking.md`

**用途**：记录待修复的bug及状态
**更新时机**：发现新bug、修复完成时

### 3. 技术实现文档
**文件**：`docs/TECHNICAL_DETAILS_IMPLEMENTATION.md`

**用途**：重要技术决策、架构变更
**更新时机**：架构调整、核心算法修改

### 4. Bug修复记录
**目录**：`docs/bug-fixes/`

**规则**：
- 仅当修复涉及复杂根因分析时创建独立文件
- 文件名：`bug-name-fix.md`（kebab-case）
- 必须包含：问题、根因、修复方案、验证结果

### 5. OpenWiki文档
**目录**：`openwiki/`

**规则**：
- 仅更新现有7个文档
- 架构/API/数据库变更时同步更新
- 不得新增文档

---

## 严格禁止

### ❌ 禁止创建的文件类型

1. **会话报告**：SESSION_*.md、HANDOFF_*.md
2. **阶段总结**：PHASE_*.md、COMPLETION_*.md
3. **修复报告**：FIX_*.md（除非是复杂bug进 bug-fixes/）
4. **分析报告**：ANALYSIS_*.md、SUMMARY_*.md
5. **临时文档**：TEMP_*.md、DRAFT_*.md
6. **重复文档**：XXX_FINAL.md、XXX_COMPLETE.md

### ❌ 禁止的写作行为

1. **长篇报告**：单次写入超过200行的文档
2. **重复信息**：已在其他文档中存在的内容
3. **详尽过程**：逐步执行日志（仅记录结果）
4. **多版本文档**：XXX_v1.md、XXX_v2.md（用git管理版本）

---

## 工作流程

### 开始工作
1. 读取 `docs/WORK_LOG.md` 最后5条
2. 读取 `TODO.md` 当前任务
3. 开始实施

### 完成工作
1. 代码提交到 git
2. 追加1-3行到 `docs/WORK_LOG.md`
3. 更新 `TODO.md` 任务状态（如需要）
4. **结束，不生成任何报告文件**

### 遇到Bug
1. 如果是快速修复：记录到 `WORK_LOG.md`
2. 如果是复杂问题：
   - 追加到 `docs/reports/audit-issues-tracking.md`
   - 修复后：简要记录到 `WORK_LOG.md` + 更新追踪状态
   - 根因复杂时：创建 `docs/bug-fixes/具体bug名.md`

### 架构变更
1. 修改代码
2. 同步更新 `openwiki/architecture.md`
3. 重要决策追加到 `TECHNICAL_DETAILS_IMPLEMENTATION.md`
4. 简要记录到 `WORK_LOG.md`

---

## 例外情况（需明确批准）

以下情况可创建新文件，但**必须先询问用户**：

1. **新功能设计文档**（超过500行的复杂设计）
2. **数据迁移方案**（涉及生产数据）
3. **用户手册/指南**（面向最终用户）
4. **API对接文档**（对外集成）

---

## 检查清单

每次准备创建新文件时，自问：

- [ ] 这个信息能追加到 `WORK_LOG.md` 吗？
- [ ] 这个bug能记录到 `audit-issues-tracking.md` 吗？
- [ ] 这个内容能更新现有 `openwiki/` 文档吗？
- [ ] 如果都不行，为什么这个文档未来不会变成"历史垃圾"？

**如果无法回答最后一个问题，不要创建新文件。**

---

## 违规后果

违反此规则导致的文档冗余：
- 淹没核心信息
- 增加新成员上手成本
- 浪费存储和git历史空间
- 降低文档可信度（不知道哪个是最新）

**原则：代码是真相，文档是索引。让 git 记录历史，让工作日志记录进展。**
