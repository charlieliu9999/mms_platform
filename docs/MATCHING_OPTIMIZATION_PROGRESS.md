## 🔍 重大发现和修复

### 1. RF标准库加载bug（重大）

**问题**:
```python
# 错误代码（data_loader.py原版）
df_xray = df_all[df_all['modality_name'] == 'X线']
sub_masks = {'RF': dev == 'RF', ...}
# 从X线中筛选RF，但RF是独立模态！
```

**实际情况**:
- RF在数据库中是独立模态：`modality_name='RF'`
- 不是X线的子类型（`device_type_name='RF'`）
- 导致54条RF标准项**完全未加载**

**修复**:
```python
# 正确代码
for modality in ['CT', 'MR', 'DSA', 'MG', 'RF', 'SPECT', 'PET/CT', 'PET/MR']:
    df_mod = df_all[df_all['modality_name'] == modality]
    # 直接按modality_name加载
```

**效果**:
- RF失败: 28条 → 19条 (-9条, **-32%改善**)
- RF标准库: 0条 → **54条**

## 🐛 待解决问题

### 1. PET/CT分类问题（中等优先级）

**现象**:
- 测试数据中所有"PET/CT"项目标记为`modality=SPECT`
- 引擎已正确加载PET/CT标准库（12条）
- 但匹配时仍作为SPECT处理

**原因**:
- 测试数据来自原系统，原系统把PET/CT归类到SPECT
- 约22个PET/CT项目被错误分类

**解决方案**:
```
方案A: 智能模态识别
  - 检测输入中的"PET/CT"/"PET/MR"关键词
  - 自动路由到正确的标准库
  - 优点: 兼容原系统习惯
  - 缺点: 增加匹配复杂度

方案B: 修正测试数据
  - 批量修改CSV中的modality字段
  - PET/CT → PET/CT, PET/MR → PET/MR
  - 优点: 简单直接
  - 缺点: 与原系统不兼容
```

**建议**: 采用方案A，在预处理阶段智能识别

---

### 2. DSA介入操作缺失（最高优先级）

**问题**:
- 161条DSA失败（占失败总数49%）
- 词汇已补充：穿刺、活检、导管、PICC、栓塞等
- 标准库只有：血管造影类（28条）
- 标准库缺少：介入操作类

**典型失败案例**:
```
- 经皮穿刺乳腺活检
- 经皮穿刺抽吸术
- 非隧道式中心静脉导管置入术
- 经外周静脉置入中心静脉导管置入术(PICC)
- 经皮腔内球囊扩张(髂动脉,PTA)
- 栓塞术
```

**解决方案**:
- 从ACR-AC数据集或原系统提取介入标准项
- 预期需要80-100个标准项
- 预期效果: 匹配率+15-18%

---

### 3. DR复杂表述（中等优先级）

**问题**:
- 39条复杂表述失败
- 词汇齐全，但算法无法处理

**典型失败案例**:
```
1. 逗号分隔的多项目:
   "CT胸部(增强),CT全腹部(增强),CT盆腔(增强)"
   
2. 组合体位:
   "DR双髋关节正、侧位"
   
3. 部位+体位组合:
   "DR腹部卧位,DR骨盆正位"
```

**解决方案**:
- 预处理阶段拆分逗号分隔项
- 添加"正、侧位"等组合体位规则
- 预期效果: 匹配率+3-4%
