# 825条未匹配数据分类详解

## 一、什么是"gap"？

**gap** = 缺口、差距

在本项目中：
- **standard_lib_gap** = 标准库缺口
- **含义**：算法引擎能够解析项目（提取出部位、扫描方式等），但在标准库中查询不到对应的标准项

### 简单类比

想象你要查字典：
- **lexicon_gap（词库缺口）**：你看不懂这个字（算法无法解析）
- **standard_lib_gap（标准库缺口）**：你看懂这个字，但字典里没有（算法能解析，标准库缺失）⭐
- **unmatchable_by_design（设计上不可匹配）**：这根本不是字，是图画（不属于字典范围）

## 四、具体示例

### ⭐ standard_lib_gap（本次目标）

```
示例1：MR肩关节(直接造影)
  ✅ 算法能解析：部位=肩关节，造影方式=直接造影
  ❌ 标准库缺失：没有"直接造影"这个扫描方式
  🔧 修复方案：添加映射规则 "直接造影" → "增强"
  ✅ 修复结果：成功匹配到"MR肩关节增强"

示例2：MR脊柱脊髓(SWI序列)
  ✅ 算法能解析：部位=脊柱脊髓，序列=SWI
  ❌ 标准库缺失：标准库命名不含序列修饰语
  🔧 修复方案：剥离"SWI序列"修饰语
  ✅ 修复结果：成功匹配到"MR脊柱脊髓平扫"
```

### ❌ unsupported_modality（无法处理）

```
示例：OTHER 某某检查
  问题：OTHER不是支持的影像模态
  原因：系统只支持CT/MR/DR/US等标准影像模态
  需要：扩展模态支持（重大架构变更）
```

### ❌ unmatchable_by_design（不应处理）

```
示例：经皮穿刺引流术
  问题：这是介入治疗操作，不是影像检查
  原因：标准库只包含影像检查标准项
  结论：设计上就不应该匹配这些项目
```

### ❌ lexicon_gap（需补充词典）

```
示例：SPECT心脏显像
  问题：算法完全无法解析（连部位都提取不出来）
  原因：词典中缺少"心脏显像"相关术语
  需要：补充医学词典和关键词规则（不是本次工作）
```

## 八、总结

### 🎯 核心要点

1. **825条未匹配不是都能修复的**
   - 397条是系统边界（不算失败）
   - 223条需要其他方案（词典/规则/人工）
   - **只有168条可以通过算法优化修复** ⭐

2. **168条是唯一目标**
   - 这些项目算法能理解，只是标准库没有对应项
   - 通过优化归一化/映射规则就能修复
   - 不需要改动标准库数据

3. **本次成果**
   - 修复了26条（超出预期86%）
   - 匹配率提升0.6个百分点
   - 还可继续修复约70条

### 💡 类比理解

想象你在查一本字典：
- **825条未匹配**就像825个"查不到"的情况
- 其中**397条**根本不是字（图画、符号），字典本来就不收录
- **223条**是你不认识的字，需要先学会读音（补充词典）
- **只有168条**是你认识的字，但字典里刚好缺了这几页（standard_lib_gap）
  - 这168条才是可以通过"补页"（算法优化）来解决的
  - 其他657条需要"重新装订字典"（系统改造）或"学习生字"（词典补充）
