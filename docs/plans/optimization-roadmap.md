# MMS 匹配系统遗留问题与优化路线图

**生成日期**: 2026-08-01  
**当前匹配率**: 79.42% (1721/2167)  
**优化目标**: 85-90%

---

## 执行摘要

基于 2167 条 ACR 数据评测，已通过模态归一化修复将匹配率从 61.51% 提升至 79.42%。

**剩余 446 条未匹配项目**（20.58%），按优先级分为3类：
- 🔴 **P1 快速见效**：XR 体位词（+1%，1-2天）
- 🟠 **P2 中等价值**：NM 核医学（+6%，需确认标准库）
- 🟡 **P3 低频特殊**：CBCT/FL/ANGIO 等（+2-3%，需专项分析）

---

## 问题清单与分析

### 🔴 P1 - 高优先级（快速见效）

#### 问题 1: XR 体位词不足

**影响范围**: 69 条未匹配（3.2%）  
**当前匹配率**: 122/191 = 63.9%  
**目标匹配率**: 75-80%

**典型未匹配案例**:
```
[XR] DR正位                    (2条)
[XR] DR正、侧位                (2条)
[XR] RF关节造影                (6条)
```

**根本原因**:
1. 体位词（正位、侧位、斜位）未被识别
2. 组合体位（正、侧位）分词失败
3. RF 可能被误分类为 XR

**解决方案**:

**方案 1: 补充体位词到 phrase_map 表**（推荐）
```sql
INSERT INTO phrase_map (source, target, category, modality) VALUES
('正位', '正位', '体位', 'DR'),
('侧位', '侧位', '体位', 'DR'),
('斜位', '斜位', '体位', 'DR'),
('正、侧位', '正侧位', '体位', 'DR'),
('正侧位', '正侧位', '体位', 'DR');
```

**方案 2: 修改 NLP Pipeline 分词逻辑**
- 在预处理阶段识别体位词
- 标准化多体位表达（"正、侧位" → "正侧位"）

**预期效果**:
- 修复: +21条
- 新匹配率: 143/191 = 74.9%
- 总匹配率: 79.42% → 80.39% (+1.0%)

**实施成本**: 1-2 天（取决于选择方案）

---

### 🟠 P2 - 中优先级（价值大但需确认）

#### 问题 2: NM 核医学数据未匹配

**影响范围**: 137 条未匹配（6.3%）  
**当前匹配率**: 0/137 = 0%

**高频未匹配项目**:
```
[NM] SPECT局部骨显像           (31条)
[NM] SPECT三时相骨显像         (9条)
[NM] PET/CT局部                (8条)
[NM] PET/CT躯干                (7条)
[NM] SPECT甲状腺显像           (7条)
[NM] SPECT全身骨显像           (5条)
```

**标准库支持情况**（从迁移文件确认）:
```python
MODALITY_CODE_MAP = {
    'SPECT': 12,    # ✅ 支持
    'PET/CT': 10,   # ✅ 支持
    'PET/MR': 11,   # ✅ 支持
}
```

**结论**: ✅ **标准库支持 NM 相关模态**

**根本原因**:
1. 模态归一化映射表已有 `'NM': 'NM'`，但标准库使用 `'SPECT': 12`
2. 需要区分：
   - SPECT 显像 → 模态代码 12
   - PET/CT → 模态代码 10
   - PET/MR → 模态代码 11

**解决方案**:

**Step 1: 验证标准库数据**
```sql
SELECT modality_code, modality_name, COUNT(*) 
FROM nlp_checkitem_standard 
WHERE modality_code IN ('10', '11', '12')
GROUP BY modality_code, modality_name;
```

**Step 2: 优化模态归一化**

当前映射不够精确：
```python
# 当前（不够细分）
'NM': 'NM',
'SPECT': 'NM',
'PET': 'PET',
```

应改为：
```python
# 优化后（精确映射到标准库代码）
'NM': 'SPECT',        # 核医学默认映射到SPECT
'SPECT': 'SPECT',     # 对应模态代码12
'PET': 'PET/CT',      # PET默认映射到PET/CT
'PET/CT': 'PET/CT',   # 对应模态代码10
'PET-CT': 'PET/CT',
'PET/MR': 'PET/MR',   # 对应模态代码11
'PET-MR': 'PET/MR',
```

**Step 3: 补充核医学关键词**

SPECT 检查项目特征：
- 骨显像、甲状腺显像、心肌显像等
- 需要在关键词引擎中添加核医学词汇

**预期效果**:
- 修复: +100-120条（假设 75-85% 匹配率）
- 总匹配率: 79.42% → 84-85% (+5-6%)

**实施成本**: 2-3 天
1. 验证标准库数据（0.5天）
2. 优化模态映射（0.5天）
3. 补充核医学词汇（1-2天）
4. 测试验证（0.5天）

### 🟡 P3 - 低优先级（特殊场景）

#### 问题 3: ANGIO 低匹配率

**影响范围**: 60 条未匹配（2.8%）  
**当前匹配率**: 27/87 = 31.0%

**未匹配案例分析**:
```
[ANGIO] DSA右心导管检查术        (2条) - 诊断性检查
[ANGIO] DSA腹主动脉支架置入术    (2条) - 介入手术
[ANGIO] DSA髂动脉支架置入术      (2条) - 介入手术
```

**原因分析**:
1. 已映射 `ANGIO→DSA`，但标准库可能主要是诊断性造影
2. 介入手术类项目（支架置入术）可能不在标准库
3. 心导管检查是特殊检查，可能词汇不足

**建议**:
- 低优先级，先做 P1/P2
- 需要人工审核未匹配的 60 条具体内容
- 可能需要区分：诊断性造影 vs 介入治疗

## 风险与缓解

### 风险 1: 核医学标准库数据不足
- **概率**: 中
- **影响**: 无法达到 +5-6% 提升
- **缓解**: 先验证标准库，确认数据量后再制定方案

### 风险 2: 体位词过度匹配
- **概率**: 低
- **影响**: 误匹配率上升
- **缓解**: 严格限定体位词的适用模态（仅 DR/XR）

### 风险 3: 修改引入新问题
- **概率**: 低
- **影响**: 已匹配项目失效
- **缓解**: 回归测试，对比修改前后的匹配结果
