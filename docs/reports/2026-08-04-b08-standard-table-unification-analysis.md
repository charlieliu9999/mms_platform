# B-08 标准库双真相源问题分析报告

**日期**: 2026-08-04  
**问题**: 系统中存在两张标准项目表，数据已分叉，导致不同模态使用不同数据源

---

## 一、问题确认

### 1.1 两张表的基本情况

| 表名 | 总行数 | 启用行数 | 唯一编码数 | 用途 |
|------|--------|----------|------------|------|
| `nlp_checkitem_standard` | 19,723 | 2,169 | 1,434 | NLP Pipeline 引擎（CT/MR/DR） |
| `standard_check_items` | 1,916 | 1,916 | 1,916 | 关键词引擎（US/SPECT/PET）+ 管理UI |

### 1.2 数据分叉情况

```
旧表独有编码：67 个（4.7%）
新表独有编码：549 个（28.6%）
共同编码：1,367 个（交集占旧表95.3%，占新表71.4%）
```

**审计报告准确**：交集确实约 67-71%，数据已严重分叉。

## 三、代码使用情况

### 3.1 使用 nlp_checkitem_standard 的模块

1. **NLP Pipeline 引擎** (`engine/match_engine_v2/data_loader.py`)
   - 加载标准库用于 CT/MR/DR 等模态的 NLP 匹配

2. **管理API** (`api/admin.py`)
   - 统计接口
   - 标准库浏览接口
   - 版本管理

3. **规则版本计算** (`core/rule_version.py`)
   - 版本指纹计算包含此表

### 3.2 使用 standard_check_items 的模块

1. **关键词引擎** (`engine/keyword/us_spect_pet_matcher.py`)
   - US/SPECT/PET/OCT/DSA 模态的关键词匹配
   - 直接查询此表进行部位映射

2. **Agent 语义匹配** (`agent/semantic_matcher.py`)
   - LLM 辅助的语义匹配
   - 按模态加载候选标准项

3. **管理API部分功能** (`api/admin.py`)
   - 部位层级数据（body_part_l1/l2/l3）

## 四、问题影响

### 4.1 功能性影响

1. **匹配结果不一致**
   - CT检查走NLP Pipeline → 旧表
   - US检查走关键词引擎 → 新表
   - 同一医嘱在不同模态下可能得到不同编码

2. **管理界面混乱**
   - 前端展示来自新表
   - 但NLP引擎实际使用旧表
   - 运营人员"改了不生效"

3. **数据孤岛**
   - 新表独有的549个编码，NLP引擎永远匹配不到
   - 旧表独有的67个编码，关键词引擎无法使用

### 4.2 运维影响

1. **双倍维护成本** - 两张表都需要维护
2. **数据同步风险** - 手工同步容易遗漏
3. **版本管理混乱** - 版本指纹只考虑旧表

---

## 五、修复方案

### 方案A：统一到新表 `standard_check_items`（推荐）

**理由**：
1. ✅ 新表设计更合理（item_code唯一约束、外键关联、状态字段完整）
2. ✅ 已有管理界面支持
3. ✅ 关键词引擎已适配
4. ✅ 可扩展性强（有外键关联多个业务表）

**工作量**：
1. NLP Pipeline 数据加载器改读新表（核心修改）
2. 管理API统一使用新表
3. 数据迁移：将旧表独有的67个编码补充到新表
4. 规则版本计算逻辑调整

**风险**：中等（需全量回归测试）

---

### 方案B：统一到旧表 `nlp_checkitem_standard`

**理由**：
1. ✅ NLP引擎已适配（核心引擎无需改动）
2. ✅ 数据历史完整（19,723行含历史版本）

**缺点**：
1. ❌ 表结构设计老旧（37个字段，层级冗余）
2. ❌ 无唯一约束，可能有重复编码
3. ❌ 关键词引擎需大幅改造

**工作量**：
1. 关键词引擎改读旧表（需适配字段差异）
2. Agent语义匹配改读旧表
3. 数据迁移：将新表独有的549个编码补充到旧表
4. 管理界面字段映射调整

**风险**：高（关键词引擎稳定性影响大）

---

### 方案C：建立同步机制（不推荐）

通过触发器/定时任务同步两张表。

**缺点**：
1. ❌ 治标不治本，长期维护成本高
2. ❌ 同步延迟导致数据不一致窗口
3. ❌ 字段映射复杂（两表结构差异大）
