# VERSION_FALLBACK 大小写修复报告

**日期**: 2026-08-20  
**问题**: 整体匹配率 67.5%，远低于预期的 98%+

---

## 问题诊断

### 现象

DR 引擎 3 个 bug 修复后（commit d891753），测试结果显示：
- DR 匹配率：仅 47.2%（预期 99%）
- CT 匹配率：90.0%（预期 99%+）
- MR 匹配率：65.4%（预期 99%+）
- 整体匹配率：67.5%

### 调查过程

#### 1. 检查 NLP Pipeline
```
输入: 颈椎正侧位
分词: ['颈椎', '正侧位'] ✓
解析: body=颈椎, position=正侧位 ✓
```

#### 2. 检查标准库
```
DR 标准库: * DR颈椎正、侧位 (body=颈椎, position=正、侧位)
用户输入: position=正侧位 (无顿号)
```

**发现**：标准库用 `正、侧位`（带顿号），用户输入是 `正侧位`（无顿号）

#### 3. 检查短语映射
```sql
SELECT * FROM nlp_phrase_map 
WHERE modality='DR' AND step='normalize' AND src_word='正侧位';

结果: 正侧位 → 正、侧位 (version='V3.8')
```

**短语映射规则存在！** 但为什么没生效？

#### 4. 检查归一化过程
```python
tokenizer.get_standard_name('正侧位', 'position', 'DR', 'v3.8.2')
# 返回: ('正侧位', 'position')  ❌ 应该返回 ('正、侧位', 'position')
```

**归一化失败！**

#### 5. 检查版本匹配
```python
# 查询时使用
version = 'v3.8.2' (小写)

# VERSION_FALLBACK
'v3.8.2': ['v3.8.2']  ❌ 只有一个值，不会 fallback

# 短语映射规则
version = 'V3.8' (大写)

# 查询失败！
```

---

## 根本原因

**VERSION_FALLBACK 大小写不兼容**

```python
# 修复前
VERSION_FALLBACK = {
    'V3.8.2': ['V3.8.2', 'V3.8'],  # 大写版本有 fallback
    'v3.8.2': ['v3.8.2'],          # 小写版本没有 fallback ❌
}

# 查询流程
1. API 传入 version='v3.8.2' (小写)
2. get_standard_name() 查询 fallback: ['v3.8.2']
3. 在 normal_rules 中查找: version='v3.8.2' ❌ 找不到
4. 短语映射规则的版本是: version='V3.8' (大写)
5. 归一化失败！
```

---

## 修复方案

### 代码修改

**文件**: `src/match_service/engine/match_engine_v2/constants.py`

```python
VERSION_FALLBACK: Dict[str, List[str]] = {
    'V3.9': ['V3.9', 'V3.8.2', 'V3.8'],
    'V3.8.2': ['V3.8.2', 'V3.8'],
    'V3.8': ['V3.8', 'V3.8.2'],
    # 小写版本兼容（Bug修复：短语映射规则使用大写版本，需要 fallback）
    'v3.9': ['v3.9', 'V3.9', 'V3.8.2', 'V3.8', 'v3.8.2', 'v3.8'],
    'v3.8.2': ['v3.8.2', 'V3.8.2', 'V3.8', 'v3.8'],
    'v3.8': ['v3.8', 'V3.8', 'V3.8.2', 'v3.8.2'],
}
```
