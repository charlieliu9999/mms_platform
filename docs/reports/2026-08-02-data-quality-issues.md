# 标准项目数据问题总结与解决方案

**日期**: 2026-08-02  
**状态**: 🟡 部分完成，发现数据质量问题

## 问题发现

### 1. 数据导入的编码问题 🔴

**问题描述**：
导入脚本的 `generate_checkitem_code()` 函数只基于**模态+部位+扫描方式**生成编码，没有包含能区分具体检查项目的唯一信息。

**示例**：
```
US模态，同一个编码 40010000110000 对应多个不同检查：
- US颌面部常规超声检查
- US经颅脑实质超声(TCS)  
- US经颅彩色多普勒超声检查（TCCD）
```

**影响**：
- 数据库中有大量重复编码
- 无法通过编码唯一定位检查项目
- 版本去重逻辑失效（同编码的记录会被误删）

**根本原因**：
```python
# 错误的编码生成方式
def generate_checkitem_code(modality_code, one_level_code, scan_code):
    return f"{device_type_code}{one_level_code}0000{scan_code}0000"
    # 缺少能区分具体检查项目的信息！
```

---

### 2. 版本清理导致数据丢失 🔴

**问题描述**：
执行版本清理时，脚本按 `checkitem_code` 去重，只保留每个编码的最新版本。由于编码重复，导致：

| 模态 | 导入数量 | 清理后 | 丢失 |
|------|---------|--------|------|
| US | 583条 | 15条 | **568条** |
| PET | 55条 | 5条 | **50条** |
| OCT | 10条 | 2条 | **8条** |
| NM | 78条 | 11条 | **67条** |

**总计丢失**: 约 **960条** 新导入的数据

**操作**：
- ✅ 已回滚，恢复所有14,597条被删除的数据
- ✅ 当前激活数据：19,723条

---

### 3. 版本管理混乱 🟡

**现状**：
数据库中有**11个版本**，包含大量重复：

| 版本 | 数据量 | 状态 | 说明 |
|------|-------|------|------|
| V3.8.2 | 1,395 | 激活 | 最新ACR标准库 |
| V3.8 | 2,875 | 激活 | 旧版本 |
| V3.7.x | 6,162 | 激活 | 多个旧版本 |
| V3.0-V3.6 | 5,664 | 激活 | 更旧版本 |
| V1.0-imported | 1,028 | 激活 | 新导入数据 |

**问题**：
- CT/MR/DR 模态有多个版本的重复数据
- 无法简单地"只显示最新版本"（因为不同检查项目的最新版本不同）
- 匹配引擎加载了大量冗余数据

## 根本解决方案

### 方案A: 修复导入脚本（推荐）🌟

**核心**: 使用原系统的 `semantic_id` 作为唯一标识

```python
# 修改导入逻辑
await conn.execute("""
    INSERT INTO nlp_checkitem_standard (
        checkitem_code,        # 使用原系统的semantic_id
        checkitem_name,
        ...
    ) VALUES ($1, $2, ...)
""",
    row['semantic_id'],        # PR0017, PR0030等
    row['name_zh'],
    ...
)
```

**优点**：
- ✅ 每个检查项目有唯一编码
- ✅ 可追溯到原系统数据
- ✅ 支持版本去重
- ✅ 与原系统保持一致

**实施步骤**：
1. 删除已导入的V1.0-imported数据（1,028条）
2. 修改导入脚本使用semantic_id
3. 重新导入数据
4. 验证数据唯一性

---

### 方案B: 清理重复版本

如果不修复导入脚本，可以清理CT/MR/DR的旧版本：

**策略**：
- 保留V3.8.2（最新版本）
- 删除V3.8, V3.7.x, V3.0-V3.6（旧版本）
- 保留V1.0-imported（新导入数据）

**预期效果**：
- 删除约 14,000条 CT/MR/DR旧版本数据
- 保留 V3.8.2 (1,395条) + V1.0-imported (1,028条)
- 总数：约 2,400 - 5,000条

**风险**：
- ⚠️ V1.0-imported数据的编码重复问题仍然存在
- ⚠️ 无法通过编码唯一查询检查项目

---

### 方案C: 数据库重构

**长期方案**：
1. 添加唯一性约束：`UNIQUE(checkitem_code, version)`
2. 添加原始ID字段：`source_id`（存储semantic_id）
3. 修改编码规则：使用语义化编码
4. 建立版本管理机制：
   - `is_active`: 是否激活
   - `is_latest`: 是否最新版本
   - `deprecated_at`: 弃用时间
