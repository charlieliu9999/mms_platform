# 失败案例根因分析报告

**数据来源**: Task #6 冒烟测试（1000条）中的 80 条失败案例  
**分析时间**: 2026-07-29  
**目标**: 识别算法缺陷，提出优化方向

---

## 1. 失败原因分布

| 原因 | 数量 | 占比 | 严重程度 |
|------|------|------|---------|
| **wrong_match** | 66 | 82.5% | 🔴 高 - 误导用户 |
| **missing_word** | 11 | 13.8% | 🟡 中 - 词库缺失 |
| **complex** | 3 | 3.8% | 🟢 低 - 合理失败 |

## 2. wrong_match 深度分析（66条）

### 2.1 核心问题：部分匹配优先于完整匹配

**问题模式 #1: "三维重建"劫持完整描述**

在 10 个案例中，有 **5 个** 被错误匹配到 `* CT三维重建`，而忽略了具体部位：

```
案例 2: "胸部CT平扫,右肩关节CT平扫" 
  期望: * CT胸部(平扫+三维重建)
  实际: * CT三维重建  ← 只匹配到"三维"，丢失了"胸部"

案例 4: "颌面部三维"
  期望: * CT颌面部(平扫+三维重建)
  实际: * CT三维重建  ← 同样问题

案例 8: "腰椎椎体（三维）,全腹部CT平扫"
  期望: * CT腰椎(平扫+三维重建)
  实际: * CT三维重建  ← 同样问题
```

**根因**: NLP pipeline 的特征提取可能过度依赖"三维重建"这个强特征，导致：
1. 部位信息（胸部/颌面部/腰椎）被低估
2. "三维重建"作为独立标准项的权重过高
3. 没有强制要求"部位+三维"的组合匹配

**置信度矛盾**: 这些错误匹配的置信度是 **0.4-0.6**（degraded/ambiguous），说明算法自己也不确定，但仍然返回了错误结果。

---

**问题模式 #2: 复合项目中只匹配最后一个**

```
案例 5: "右股骨中上段正侧位;右股骨中下段正侧位;颈椎正侧位片;腰椎正侧位;"
  期望: * DR右股骨正、侧位  ← 第一个项目
  实际: * DR颈椎正、侧位    ← 匹配到了第三个项目
  置信度: 0.4
```

**根因**: 
- 分号分隔的多项目描述中，算法可能按顺序扫描，最后出现的"颈椎"覆盖了前面的"股骨"
- 没有"主项目优先"的启发式规则（通常第一个项目是主检查）

---

**问题模式 #3: "完全匹配"被判定为错误（实际上是标注问题）**

```
案例 1: "内耳道CT平扫,副鼻窦CT平扫"
  期望: * CT内耳乳突部(平扫)
  实际: * CT内耳及中耳乳突(平扫)  ← 更精确的描述
  置信度: 1.0

案例 3: "泌尿系平扫、增强、CTU"
  期望: * CT尿路造影成像(CTU)
  实际: * CT全泌尿系(平扫+增强+CTU)  ← 包含了所有项
  置信度: 1.0
```

**置信度矛盾**: 算法给出了 **1.0 置信度**（完全确定），但被标为"错误"。

**根因**: 这可能是**标注数据的问题**，而非算法缺陷：
- 案例1: "内耳及中耳乳突" 比 "内耳乳突部" 更完整
- 案例3: "平扫+增强+CTU" 比单独 "CTU" 更准确

**建议**: 将这些案例提交人工复核，可能需要更新标注。

### 2.2 按模态分布

| 模态 | wrong_match 数量 | 占该模态失败的比例 |
|------|-----------------|-------------------|
| CT | 42 | 89.4% (42/47) |
| DR | 10 | 76.9% (10/13) |
| MR | 14 | 70.0% (14/20) |

**结论**: CT 的 wrong_match 问题最严重，可能因为：
- CT 描述通常包含更多修饰词（平扫/增强/三维）
- CT 的复合检查更常见
- NLP pipeline 对 CT 的特征提取优先级设置不当

## 3. missing_word 分析（11条）

### 3.1 缺失模式

**缺失类型 #1: 简写未识别**

```
"血管成像(MRA)" → 期望: * MR动脉血管成像(MRA)
"鼻窦平扫+DWI"  → 期望: * MR弥散加权成像(DWI)
```

**根因**: 
- 医学词典中可能只有 "动脉血管成像(MRA)"，没有单独的 "血管成像(MRA)"
- "DWI" 作为独立关键词未收录

**修复**: 扩充医学词典，增加常见简写变体。

---

**缺失类型 #2: DR 特殊格式**

```
"DR_足斜位_DR_足正位_DR等大影像或放大影像" → 期望: * DR双足正、斜位
"DR_手斜位_DR_手正位_DR等大影像或放大影像,..." → 期望: * DR双手正、斜位
```

**根因**: 
- DR 系统导出的特殊格式 `DR_部位_体位_DR等大影像...` 未被识别
- 算法没有处理这种"下划线分隔+重复模态"的模式

**修复**: 预处理阶段增加 DR 格式归一化规则。

---

**缺失类型 #3: 边界词汇**

```
"6岁以下胸片(DR)（床旁）" → 期望: * DR胸部(床旁机)
"CT引导"                   → 期望: * CT临床操作的CT引导
"上颌部CT平扫+增强"        → 期望: * CT上颌骨(平扫+增强)
```

**根因**: 
- "6岁以下"前缀未处理
- "CT引导"作为操作类项目未收录
- "上颌部" vs "上颌骨" 的词形变化未覆盖

**修复**: 增加年龄前缀清洗规则、操作类项目词库、解剖部位同义词。

## 4. complex 分析（3条）

```
"[下腹部]16排以上螺旋X线计算机体层(CT)其它增强扫描(医保),[上腹]16排以上螺旋X线计算机体层(CT)其它增强"
```

这类超长、包含多个部位、带有计费标识的复合描述，**合理失败**。建议由 L3 AI Agent 处理。

## 5. 优化建议（按优先级）

### 🔴 P0 - 立即修复（影响82.5%失败）

**1. 特征权重重新校准**
- **问题**: "三维重建"权重过高，掩盖部位信息
- **方案**: 
  - 在 NLP pipeline 中强制要求 `部位 + 三维重建` 组合匹配
  - 如果只匹配到"三维重建"而无部位，降级为 `ambiguous`（confidence < 0.8），不进入 L1

**2. 复合项目优先级规则**
- **问题**: 多项目描述中后出现的项目覆盖前面的
- **方案**:
  - 分号/逗号分隔后，优先匹配第一个完整描述
  - 或返回多个候选，由用户/Agent 选择

**3. 标注数据复核**
- **问题**: 高置信度（1.0）的"错误"匹配可能是标注错误
- **方案**: 
  - 筛选 `confidence >= 0.9 AND is_correct = false` 的案例
  - 提交人工复核，可能需更新 expected_standard

---

### 🟡 P1 - 短期优化（影响13.8%失败）

**4. 医学词典扩充**
- 增加常见简写: MRA（单独）、DWI（单独）、CTU（单独）
- 增加解剖部位同义词: 上颌部↔上颌骨、内耳道↔内耳乳突部

**5. DR 格式预处理**
- 识别并归一化 `DR_部位_体位_DR等大...` 格式
- 提取部位和体位组合

**6. 前缀/后缀清洗**
- 移除年龄前缀: "6岁以下"、"成人"、"儿童"
- 移除计费标识: "(医保)"、"[...]"

---

### 🟢 P2 - 长期优化

**7. L2→L3 智能路由**
- 对于 `confidence < 0.6` 且 `tier = ambiguous` 的结果
- 自动标记为"需 Agent 审核"，不直接返回给用户

**8. 用户反馈闭环**
- 收集线上用户对"wrong_match"的纠正
- 自动更新到 match_feedback 供 Agent 学习

---

## 6. 预期改进效果

如果实施 P0 优化（特征权重 + 复合项目规则 + 标注复核）：

| 指标 | 当前 | 预期 |
|------|------|------|
| 准确率 | 93.31% | **96-97%** |
| wrong_match | 66条 | **<30条** |
| confidence < 0.8 的 wrong_match | ~40条 | **<10条** |

**依据**: 
- "三维重建"劫持问题占 ~30% 的 wrong_match（20条）
- 标注复核可能纠正 10-15 条高置信度"假错误"
- 复合项目规则可修复 ~10 条

## 7. 快速验证方案

在全量结果出来后：

```bash
# 1. 筛选高置信度"错误"（可能是标注问题）
poetry run python -c "
SELECT check_item, expected_name, actual_name, confidence 
FROM mms_eval_details 
WHERE task_id=7 AND is_correct=false AND confidence >= 0.9
ORDER BY confidence DESC LIMIT 50
"

# 2. 筛选"三维重建"劫持案例
SELECT check_item, expected_name, actual_name 
FROM mms_eval_details 
WHERE task_id=7 
  AND is_correct=false 
  AND actual_name LIKE '%三维重建%'
  AND expected_name NOT LIKE '%三维重建%'

# 3. 统计各类 wrong_match 的占比
SELECT 
  CASE 
    WHEN actual_name = '* CT三维重建' THEN 'CT三维重建劫持'
    WHEN confidence >= 0.9 THEN '高置信度错误'
    WHEN check_item LIKE '%;%;%' THEN '复合项目'
    ELSE '其他'
  END as pattern,
  COUNT(*) as count
FROM mms_eval_details
WHERE task_id=7 AND failure_reason='wrong_match'
GROUP BY pattern;
```
