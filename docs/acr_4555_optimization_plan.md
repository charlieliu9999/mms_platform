## 可优化类别 (197 项, 30.5%)

### 优先级 1: standard_lib_gap (91 项)

**问题**: 引擎能解析医学实体，但标准库缺少对应项目

#### 按模态分布
- **MR** (19 项): 脊髓动脉血管成像、支气管、肾静态显像等
- **DR** (17 项): 阴道造影、正/侧位等体位描述
- **XR** (15 项): 全身骨骼、骨骼发育评估等
- **US** (13 项): 静脉导管、双胎输血综合征、全脊柱等
- **CT** (10 项): 脊柱局部、脊髓动脉血管成像等
- **SPECT** (9 项): 心脏显像、全身显像、膀胱显像等
- **RF** (8 项): 盆腔淋巴管造影、血管造影等

#### 优化方案

**Phase 1: 快速补充（预计 +30 项）**

1. **SPECT 核心显像项目** (9 项)
   ```sql
   -- 补充 SPECT 常见显像项目
   INSERT INTO standard_check_items (item_code, item_name, modality, ...) VALUES
   ('50xxx', '* SPECT心脏显像', 'SPECT', ...),
   ('50xxx', '* SPECT全身显像', 'SPECT', ...),
   ('50xxx', '* SPECT膀胱显像', 'SPECT', ...);
   ```

2. **DR/XR 体位标准化** (10 项)
   - 补充 "正位"、"侧位"、"正、侧位" 等通用体位项目
   - 或增强词表将这些映射到现有标准项

3. **US 特殊检查** (6 项)
   - 静脉导管超声、双胎输血综合征、全脊柱超声
   - 这些是真实临床需求，需要补充标准编码

4. **MR 血管成像** (5 项)
   - 脊髓动脉血管成像、支气管增强等

**Phase 2: 系统性补充（预计 +40 项）**

1. 与临床科室确认 DR/XR 体位项目的标准化方案
2. 补充 CT/MR 的罕见部位检查（脊髓造影、原发部位等）
3. 补充 RF 造影类项目（需确认编码规范）

**预期收益**: 匹配率 +2.0% (85.82% → 87.82%)

### 优先级 3: standard_data_conflict (17 项)

**问题**: 标准库中存在同名多编码，引擎无法自动选择

#### 典型案例
- CT全脊柱(增强) - 多个编码冲突
- MR眼眶(平扫+增强) - 同名项目
- SPECT放射性核素大动脉显像 - 新旧编码共存

#### 优化方案

**Phase 1: 数据清理（预计 +15 项）**

1. **审查同名项目**
   ```sql
   -- 查找同名多编码
   SELECT item_name, array_agg(item_code) as codes, COUNT(*)
   FROM standard_check_items
   WHERE is_active = true AND version = 'v3.8.2'
   GROUP BY item_name
   HAVING COUNT(*) > 1;
   ```

2. **确定优先编码**
   - ACR 标准编码优先
   - 标记非优先编码为 `is_active = false` 或添加备注

3. **迁移历史数据**
   - 将使用旧编码的匹配记录迁移到新编码

**Phase 2: 算法增强**

1. 增强 `_select_by_code_priority` 逻辑
2. 当无法自动选择时，返回置信度较低的 degraded tier
3. 记录到 audit log 供人工审核

**预期收益**: 匹配率 +0.4% (88.82% → 89.22%)

### 优先级 4: parser_ambiguity (16 项)

**问题**: 包含多个检查的复合项目，或 "或" 逻辑描述

#### 典型案例
1. **联合检查**: "US盆腔(经阴道+经腹部多普勒)联合CT盆腔腹部(平扫+增强)"
2. **或逻辑**: "MR肾脏(平扫+增强)或SPECT/CT肾脏(99mTc-DMSA静态显像)"
3. **多部位**: "X线消化道造影(全消化道钡餐/碘水造影)"

#### 优化方案

**Phase 1: 拆分策略（预计 +8 项）**

1. **识别 "联合" 关键词**
   - 在预处理阶段拆分为多个独立项目
   - 分别匹配后合并结果

2. **识别 "或" 逻辑**
   - 标记为需要人工选择的 ambiguous 项目
   - 或提取两个选项分别匹配，返回多候选

**Phase 2: 标准化指南（预计 +6 项）**

1. 与临床协商：联合检查是否应拆分为两条记录
2. "或" 逻辑项目是否应在上游系统明确选择

**预期收益**: 匹配率 +0.5% (89.22% → 89.72%)

---

### 优先级 5: modality_route_review (11 项)

**问题**: 文本模态与指定模态不一致，需要人工审核

#### 典型案例
- [DR] X线小肠造影检查 - 可能应该是 RF
- [OTHER] 核素肺通气/灌注显像 - 应该是 SPECT

#### 优化方案

**Phase 1: 路由规则增强（预计 +8 项）**

1. **增强模态推断规则**
   ```python
   # modality_resolver.py
   ROUTING_KEYWORDS = {
       '造影': 'RF',  # 造影类检查优先路由到 RF
       '核素': 'SPECT',  # 核素显像路由到 SPECT
   }
   ```

2. **审核规则白名单**
   - 确认安全的自动路由模式
   - 减少需要人工审核的项目

**预期收益**: 匹配率 +0.3% (89.72% → 90.02%)
