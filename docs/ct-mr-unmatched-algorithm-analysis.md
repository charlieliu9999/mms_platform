# CT/MR 未匹配项算法归因分析

> 日期：2026-08-04
> 范围：`unmatched_registry` 中 `status='open'` 且模态 ∈ {CT, CT-DE, CT-4D, MR}
> 方法：逐项重跑 `match_engine_v2`，结合 pipeline trace + `standard_check_items` 标准库对照

## 0. 结论速览

对 **115 个去重后的 open CT/MR 项** 重跑引擎并归因：

| 根因类别 | 数量 | 占比 | 性质 |
|---|---|---|---|
| **H. 纯标准库缺口**（部位+扫描无对应项） | 31 | 27% | 数据 |
| **D. 血管成像标准项缺口**（MRA/CTA/MRV） | 27 | 23% | 数据 |
| **C. 功能序列组合不匹配**（平扫+DWI / DCE） | 19 | 17% | **算法可修** |
| **G. 特殊序列/后处理修饰**（Haste/STIR/MPR/VR…） | 14 | 12% | 数据为主 |
| **A. 设计不可匹配**（引导/穿刺/定位/消融） | 10 | 9% | 正确，无需处理 |
| **E. 新技术/跨模态**（能谱/双能/4D/PET-MR） | 9 | 8% | 词库 |
| **B. 方括号修饰语被拆分**（面神经[颅外段]） | 3 | 3% | **算法 Bug** |
| **F. 多项记录部分失配** | 2 | 2% | 算法 |

**一句话结论**：CT/MR 未匹配的**主要矛盾不是解析算法，而是标准库缺口（约 60%）**；解析/部位归一化整体健康。算法侧最值得修的是 **①扫描方式组合匹配过严（平扫+DWI/DCE 无法降级，~19 项）** 和 **②方括号修饰语被误拆分（~3 项，标准项明明存在）**。

## 2. 根因详解（附 trace 证据）

### 2.1 【数据·最大头】标准库缺口（H+D+E ≈ 67 项，58%）

解析出的 `部位+扫描方式` 组合在 `standard_check_items` 中**根本不存在**。实测对照：

| 未匹配项 | 解析结果 | 标准库现状 |
|---|---|---|
| MR头颈部(平扫+增强) | body=头颈部, scan=平扫+增强 | 仅有头颈部**血管** MRA/CE-MRA/VWI，无平扫项 |
| MR全消化道(平扫) | body=全消化道 | `消化道` 命中 0 条 |
| CT乳腺(平扫+增强) | body=乳腺 | CT 模态下 `乳腺` 命中 0 条（乳腺归 MG） |
| CT全脊柱(增强) | body=全脊柱, scan=增强 | 仅有全脊柱(平扫)/(平扫+三维重建)，无增强 |
| MR肺动脉血管成像(MRA) | body=肺动脉, scan=MRA | 仅有肺动脉 **CE-MRA**，无平扫 MRA |
| MR上肢静脉血管成像(MRV) | body=上肢静脉, scan=MRV | 仅有上肢**动脉** MRA/CE-MRA，无静脉 MRV |
| MR关节(平扫) | body=四肢及关节 | 58 条均为具体关节（左肘/双膝…），无泛化"关节" |

> **判定**：这类需要**补充标准库**（新增 item），不是算法能解决的。

### 2.2 【算法·最值得修】扫描方式组合匹配过严（C，19 项，17%）

医嘱写 `平扫+DWI`、`平扫+动态增强`，但标准库把功能序列建模为**单一扫描方式**。

**证据**（trace + 标准库）：
- `MR脑(平扫+DWI)` → 节点 scan 被 remap 成整串 `平扫+DWI`；`_query_ct_mr` 用 `scan_name.isin(['平扫+DWI'])` 精确匹配。
- 标准库中 `scan_method='平扫+DWI'` 只有 **1 条**（MR全脊柱）；颅脑只有 `弥散加权成像(DWI)`。→ 查不到。
- `MR盆腔动态增强扫描(DCE-MRI)` → scan=`动态对比增强(DCE-MRI)`；标准库 DCE 项只挂在 乳腺/前列腺/垂体/肝脏/非指定部位，盆腔无。

**修复方向**：在 `_query_ct_mr` 增加**扫描组合降级**——当 `平扫+X` 精确匹配为空时，回退尝试功能序列 `X`（DWI/DCE/MRS 等），命中则标 `degraded`。可挽回约 19 项。

### 2.3 【算法 Bug】方括号修饰语被拆分（B，3 项）

`MR面神经[颅外段](平扫)` 的标准项**在库中真实存在**（`MR面神经[颅外段](平扫)/(增强)/(平扫+增强)`），但：

```
8-body_2process_remap:
   Node → 面神经(body) | ...      ← 主节点，lookup 命中 MR面神经(平扫)
   Node → 颅外段(body) | ...      ← 方括号内容被拆成独立 body 节点，lookup 落空
→ 一命中一空 → 降级 ambiguous
```

**根因**：`body_2process_remap` 把 `[颅外段]` 当作独立部位拆分，破坏了"面神经[颅外段]"这一整体标准名。
**修复方向**：方括号 `[...]` 应作为前一部位的**修饰语保留**（不参与 body 拆分），或在 lookup 时用 `面神经[颅外段]` 整体去匹配。

### 2.4 【数据一致性】部位归一化不一致（隐藏放大器）

引擎把 `盆腔 → 盆腔及盆底结构`，但标准库里前列腺/子宫/DWI/DCE 等功能项的 `body_part_l2='盆腔'`。两套部位命名并存，导致**即使扫描方式对上，部位也对不上**。建议统一标准库部位字典（或在 lookup 侧建立 `盆腔 ↔ 盆腔及盆底结构` 等价映射）。

### 2.5 解析算法整体健康（正面结论）

trace 显示部位归一化工作良好，**不是瓶颈**：
- `脑 → 颅脑`、`盆腔 → 盆腔及盆底结构`、`关节 → 四肢及关节`、`肺动脉/上肢静脉/全脊柱/全消化道` 均正确识别。
- 上一轮修复的 dup_set 影子节点问题（8.6 去重）在本批未再复现。

## 3. 优先级建议

| 优先级 | 动作 | 类型 | 预期挽回 |
|---|---|---|---|
| **P1** | `_query_ct_mr` 增加扫描组合降级（平扫+X → X） | 算法 | ~19 项 |
| **P1** | 修复方括号修饰语拆分（面神经[颅外段]） | 算法 Bug | ~3 项（且消除误降级） |
| **P2** | 补充血管成像标准项（MRA/CTA/MRV 平扫及静脉） | 数据 | ~27 项 |
| **P2** | 统一部位字典（盆腔 ↔ 盆腔及盆底结构） | 数据一致性 | 放大 P1 效果 |
| **P3** | 补充纯标准库缺口项（全消化道/支气管/乳腺CT/全脊柱增强等） | 数据 | ~31 项 |
| **P3** | 新技术词库（能谱/双能/4D/PET-MR/化学位移） | 词库 | ~9 项 |
| — | 设计不可匹配项（引导/穿刺/定位） | 维持现状 | 0（正确） |

> 算法侧（P1）合计可挽回 **~22 项** 并消除一类误降级；数据侧（P2/P3）是提升上限的主战场（~67 项）。
